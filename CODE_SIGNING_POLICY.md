# Code signing policy

Virtual Scanner is applying for open-source code signing through SignPath
Foundation.

Pending approval, the project will use:

> Free code signing provided by SignPath.io, certificate by SignPath Foundation

## Signing scope

Only release artifacts built from the public source repository are eligible for
release signing:

- Windows NSIS installers
- Windows TWAIN data source files
- Release ZIP packages that contain signed artifacts

Portable ZIP packages may include signed binaries, but the ZIP container itself
is not expected to be Authenticode-signed.

## Trusted build and origin

Release artifacts are built by the repository workflow in
`.github/workflows/build.yml`. Release signing is restricted to builds produced
from this public repository.

Release signing should only be used for:

- Tags matching `v*`
- The `main` branch when preparing an official release

Signing requests must be traceable to the public Git commit used to build the
release artifact.

If additional maintainers are added, this policy should be updated before they

## Security requirements

- Maintainers with repository or signing access must use multi-factor
  authentication.
- Release artifacts must be generated by CI, not by a local manual build.
- Release downloads must be published from the GitHub Release for the matching
  version tag.
- Checksums should be published with each release so users can verify downloads.

## Incident response

If a signing credential, workflow, release artifact, or maintainer account is
suspected to be compromised, release signing should pause until the issue is
investigated and corrected. Affected releases should be replaced or withdrawn
when necessary.
